# Live measurement — 2026-08-07 · OpenAI `gpt-5.1`

The first live extraction measurement. BUILD §1.3 and the ratification packet
have carried this debt since the prompt waivers. It is discharged, and what it
found is not what anyone expected to be looking for.

## The headline: single runs cannot compare prompts here

Two consecutive runs of the **identical** prompt (v6), same corpus, same model,
nothing changed between them:

| | run 1 | run 2 |
| --- | --- | --- |
| round-trip | 7/10 | **9/10** |
| PIPE-4 criticals | 32 | **14** |
| PIPE-6 verbatim | FAIL | **100%** |

A two-check swing on the round-trip and a 2× swing in criticals, from nothing.
Every prompt-vs-prompt comparison below is therefore a **single noisy sample**,
and the differences between adjacent rows are inside that noise. They are
recorded because they happened, not because they establish anything.

EVALS already anticipates exactly this — PIPE-15 specifies k consistency runs and
a 70% flicker boundary, marked ◊ provisional. It has never been operationalized.
Until it is, **no ◊ target can honestly be assessed from this harness**, because
one run is not a measurement of a stochastic system.

## What IS causal, and was fixed

Three defects were found while measuring, and unlike the prompt rules these are
deterministic — each made a specific outcome *impossible*, not merely less likely.

1. **The prompt version was silently downgraded.** `promptVersion` ran a
   hardcoded allow-list `["v1","v2","v3"]` and substituted `"v3"` for anything
   else. Promoting v4 changed the default, the build succeeded, a live run
   completed, and every fixture came back stamped `v3`. A validation that
   quietly swaps in a *different* input cannot be distinguished from working.
   Now derived from the bundled resources, and an unknown version fails loudly.

2. **Every memo was extracted as a `portrait`.** Episodes are portraits-only
   (rule 11), so labelling ordinary captures as portraits invited reconstructed
   episodes that the goldens then counted as inventions. Only Eliah is a
   portrait. Fixing this alone moved round-trip 5→6 and criticals 24→21.

3. **The round-trip seeded a ledger and then denied it.** Priya was seeded as
   already employed at Google, James at Stripe — and the extraction ran
   primer-less, so both came back `match: "new"`. `SyncEngine` skips corrections
   and contradictions whose subject is an unresolved ref, so CORRECT and CLOSE
   could **never** be emitted, regardless of extraction quality. The harness was
   seeding a person and hiding them in the same breath. It now sends the same
   primer the app sends on device (§7.7). Round-trip 6→9.

Two of the five original failures were therefore harness bugs, not model
failures — and they had been silently inflating every "the extractor is bad"
reading.

## Where the extractor actually stands

On the best observed run: recall **67.8%** against ◊ ≥90%, criticals **14**
against 0, hedge preservation still failing. Tag discipline (PIPE-17) and
verbatim fidelity did reach target on two runs, which is the first evidence that
the FN-10/12/14 fixes hold on live output — but one clean sample of a noisy
signal is not a pass.

The honest summary: **the alternate provider is below the bar, by how much is
not yet measurable, and the harness needed three fixes before the question could
even be asked properly.**

## What would actually settle it

1. Operationalize PIPE-15: run k≥5 and report the distribution, not a point.
2. Measure the ratified primary (`claude-opus-5`) the same way — the provider
   comparison has never been made under equal conditions.
3. Only then judge prompt versions, one variable at a time, against distributions.
